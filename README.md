CASO 1: PILARBUS – ENFOQUE ÁGIL (SCRUM)
Proyecto: Aplicación móvil y plataforma web de transporte público.
1. ¿En qué consiste el proyecto?
PilarBus es una aplicación que busca facilitar el uso del transporte público en Pilar. Su objetivo es permitir que los ciudadanos puedan consultar los recorridos de los colectivos, visualizar su ubicación en tiempo real, recibir alertas sobre desvíos y acceder a otras funciones, como la integración con SUBE y un sistema de reclamos.
2. ¿Por qué se eligió la metodología Scrum?
Se eligió Scrum porque el proyecto puede presentar cambios durante su desarrollo, según las necesidades y opiniones de los usuarios.

Esta metodología permite trabajar por períodos cortos llamados Sprints, de dos semanas aproximadamente. Al finalizar cada Sprint, se obtiene una parte funcional de la aplicación que puede probarse y mejorarse.

Sus principales beneficios son:
- Adaptarse a los cambios.
- Recibir opiniones de los usuarios.
- Detectar errores rápidamente.
- Entregar funcionalidades progresivamente.
- Mejorar la comunicación del equipo.
3. Estimación de esfuerzo y costos
Para calcular el esfuerzo se utilizan Story Points y Planning Poker.

Los Story Points permiten medir la complejidad de cada tarea, mientras que Planning Poker permite que los integrantes del equipo acuerden cuánto esfuerzo requiere cada funcionalidad.

El proyecto tiene una estimación de 65 puntos y se calcula que las funcionalidades principales podrían desarrollarse en aproximadamente 4 Sprints, es decir, unas 8 semanas.

El costo estimado para los primeros dos meses es de USD 30.360, incluyendo un 10 % para imprevistos.
4. Organización del trabajo con Trello
Se utiliza Trello para organizar las tareas y controlar el avance del proyecto.

Las tareas se distribuyen en tres estados:
- To Do: tareas pendientes.
- In Progress: tareas que se están realizando.
- Done: tareas terminadas y verificadas.
Se establece un máximo de tres tareas simultáneas en progreso para evitar la acumulación de trabajo.
5. Uso de GitHub y CI/CD
GitHub permite guardar el código de la aplicación, controlar sus versiones y trabajar en equipo.

Los desarrolladores trabajan en diferentes ramas y utilizan Pull Requests para revisar los cambios antes de incorporarlos al código principal.

También se utiliza CI/CD para automatizar tres procesos:
- Build: verificar que el proyecto se construya correctamente.
- Test: realizar pruebas automáticas.
- Deploy: publicar las actualizaciones de la aplicación.
6. Conclusión del caso 1
Scrum es una metodología adecuada para PilarBus porque permite desarrollar la aplicación de manera progresiva, incorporar mejoras y adaptarse a las necesidades de los usuarios.

La combinación de Scrum, Trello, GitHub y CI/CD permite organizar el trabajo, controlar los avances, reducir errores y realizar actualizaciones frecuentes.

Idea principal: PilarBus utiliza una metodología ágil porque necesita flexibilidad, mejoras continuas y participación de los usuarios.





CASO 2: CENTRO DE CÓMPUTOS Y ANILLO DE FIBRA ÓPTICA – ENFOQUE CASCADA
Proyecto: Implementación de infraestructura tecnológica en el Campus de la Universidad Nacional de Pilar (UNP).
1. ¿En qué consiste el proyecto?
El objetivo es implementar un Centro de Cómputos y un Anillo de Fibra Óptica para mejorar la conectividad y los servicios informáticos de la universidad.

El proyecto incluye la construcción de canalizaciones, instalación de fibra óptica, incorporación de servidores, racks, UPS y equipos de red.

Finalmente, se debe configurar y probar toda la infraestructura para comprobar que funcione correctamente.
2. ¿Por qué se eligió la metodología Cascada?
Se eligió el modelo Cascada porque el proyecto tiene requisitos definidos desde el principio, un presupuesto limitado y plazos establecidos.

Además, las actividades deben realizarse en un orden determinado. Por ejemplo, primero se deben preparar las canalizaciones y después instalar la fibra óptica.

Esta metodología permite planificar, controlar y aprobar cada etapa antes de avanzar a la siguiente.
3. Etapas del proyecto
El proyecto está dividido en cinco etapas:
1. Diseño: elaboración de planos y arquitectura del proyecto. Duración: 3 semanas.
2. Licitación y adquisición: compra de servidores y equipamiento tecnológico. Duración: 5 semanas.
3. Obra civil: construcción de canalizaciones y ductos. Duración: 5 semanas.
4. Instalación: tendido de fibra óptica e instalación de hardware. Duración: 5 semanas.
5. Configuración y cierre: configuración de la red, pruebas y documentación final. Duración: 2 semanas.
La duración total estimada es de 20 semanas.
4. Estimación de recursos y costos
Para organizar el presupuesto se utilizan dos herramientas:
- WBS: permite dividir el proyecto en actividades y tareas más pequeñas.
- Bottom-Up: permite calcular el costo de cada tarea y luego sumar los valores para obtener el presupuesto total.
Se consideran profesionales como ingenieros de redes, ingenieros civiles, técnicos de infraestructura, técnicos de fibra óptica y especialistas en seguridad.

El presupuesto estimado es:
- Presupuesto base: $83.400.000.
- Contingencia del 5 %: $4.170.000.
- Presupuesto total recomendado: $87.570.000.
Los valores son estimativos y ficticios para el ejercicio académico.
5. Organización y planificación
El proyecto se organiza mediante un cronograma que permite controlar las actividades, sus duraciones y las dependencias entre ellas.

Cada etapa debe finalizar antes de comenzar la siguiente cuando existe una dependencia Fin-Inicio.

Esto permite evitar problemas durante la construcción y la instalación de los equipos.
6. Cierre del proyecto
El proyecto se considera terminado cuando:
- El Centro de Cómputos está construido.
- Los servidores, racks y UPS están instalados.
- La fibra óptica está tendida y certificada.
- La red está configurada.
- Las pruebas de conectividad funcionan correctamente.
- Se entrega la documentación técnica.
- La universidad acepta formalmente el trabajo.
7. Conclusión del caso 2
El modelo Cascada es adecuado para este proyecto porque permite organizar las actividades en etapas ordenadas, controlar los costos y respetar los tiempos establecidos.

Al tratarse de una obra que combina infraestructura física y tecnología, es importante planificar cada paso antes de ejecutarlo.

Idea principal: el proyecto utiliza Cascada porque necesita planificación previa, control del presupuesto y cumplimiento de etapas y plazos definidos.
